# ADR-001: Base de dades del projecte

## Status
Acceptat

## Context
La botiga en línia de merchandising de Kakapos necessita persistir informació
sobre un domini amb diverses entitats relacionades entre si. 
Al ser un projecte en fase inicial, l'estructura d'aquestes entitats encara 
pot canviar amb el temps, i es vol evitar modificar un esquema rígid cada vegada que 
s'afegeix o s'ajusta un camp.

## Decisió
Farem servir MongoDB com a base de dades principal, gestionada via Docker
(contenidor `ecommerce-mongo`, amb persistència mitjançant un volum amb nom).

## Conseqüències
+ Flexibilitat per a nous camps i entitats — puc anar afegint coses al
  model sense haver de fer migracions com faria amb SQL
+ Bona integració amb Node/Express, hi ha molta documentació i és fàcil
  trobar exemples
+ Docker fa que sigui fàcil tenir-ho tot muntat sense instal·lar Mongo
  directament al meu ordinador
- Com és la meva primera vegada amb MongoDB, segur que faré errors
  de disseny al principi 
- Menys adequat per a consultes molt relacionals 
- Cal gestionar manualment la integritat referencial entre entitats
  relacionades (per exemple, `Comanda` i `LineaComanda`), ja que Mongo no
  ho fa per mi com faria una primary key en SQL
